## C. Private GitHub repository: setup and owner invitation

The goal is a **private** repository the owner can access or own. GitHub Pages
stays off and no public page is created. The canonical repository stays on
ForgeJo (`origin`). GitHub is an extra remote named `github`.

### Prerequisites

1. **Owner's yes.** Do not invite anyone, or push anywhere they can see it, before
   the owner has replied positively to the email in part A.
2. **Owner's GitHub username.** GitHub invites repository collaborators **by
   username**. An email address only resolves to an account if that user has made
   the address public. Ask the owner to create a free account at
   <https://github.com/signup> with `marienbraeu@gmx.at` and send you the username.
3. **GitHub CLI** (`gh`) on the machine that runs the setup, logged in with
   `gh auth login`. It is not installed on `crew`, and crew has no GitHub access, so
   run the setup from a workstation that has a GitHub login.

### Option 1: the script (recommended)

`scripts/setup-private-github.sh` does the whole procedure with guard rails. By
default it is a **dry run**. It changes nothing until `--yes` is given.

```bash
# 1. Preview: shows every command, changes nothing
scripts/setup-private-github.sh --repo <your-account>/marienbraeu

# 2. Create the private repo and add the 'github' remote
scripts/setup-private-github.sh --repo <your-account>/marienbraeu --yes

# 3. Upload the code (main branch only)
scripts/setup-private-github.sh --repo <your-account>/marienbraeu --push --yes

# 4. After the owner said yes and sent their username
scripts/setup-private-github.sh --repo <your-account>/marienbraeu \
    --invite <owner-username> --permission admin --yes
```

If the repository already exists, pass `--url https://github.com/OWNER/marienbraeu`
or `--url git@github.com:OWNER/marienbraeu.git` instead of `--repo`.

The script will **refuse** to:

- accept `--public`, `--internal` or any visibility other than private,
- continue if the target repository is not `PRIVATE`. It checks before the first
  change, before every push and before the invite,
- continue if GitHub Pages is enabled on the repository,
- push if `main` contains a `CNAME`, a `.nojekyll` or anything under
  `.github/workflows/`, since any of these could publish the site,
- touch the existing `origin` remote, or reuse a `github` remote that points
  elsewhere.

It also turns off the repository's wiki and projects so the repo gains no public
surface.

### Option 2: by hand

**With the CLI:**

```bash
gh repo create <your-account>/marienbraeu --private --disable-wiki \
    --description "Marienbräu website — private, not published"
gh repo view <your-account>/marienbraeu --json visibility   # must say PRIVATE
git remote add github git@github.com:<your-account>/marienbraeu.git
git push github main:main
gh api -X PUT repos/<your-account>/marienbraeu/collaborators/<owner-username> \
    -f permission=admin
```

Never use `--public`, and never pass `--push` to `gh repo create` before checking
visibility.

**In the web UI:**

1. <https://github.com/new>, set the name to `marienbraeu`, choose **Private**, and
   do **not** add a README, license or `.gitignore`. The repo already has its files.
2. Push as shown above (`git remote add github …` then `git push github main:main`).
3. **Settings → Pages**: confirm that no site is configured. Leave it that way.
4. **Settings → Collaborators → Add people**: enter the owner's username, then
   choose the role.

### Handing over ownership

When the owner wants to **own** the repository rather than just access it:
**Settings → General → Danger Zone → Transfer ownership** to the owner's
account. Visibility stays private through a transfer. Afterwards ask the owner to
keep you as a collaborator if you are to continue maintaining the site.

### Going live (later, only with written permission)

Publishing is a separate decision that comes after the owner's yes. It covers the
domain, hosting and the Google Business link. Before going live, work through the
"Before going live" list in the README: real photos, confirmed prices, verbatim
reviews, Impressum and Datenschutz.
